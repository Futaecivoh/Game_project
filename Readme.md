# Потужний Кавун

Это мрачная текстовая ролевая игра с элементами Roguelike, разработанная на платформе C# (.NET). Игрок берет на себя управление героем, исследует процедурно связанные локации многослойного графа карты, принимает стратегические решения, прокачивает экипировку и сражается со смертоносными врагами и финальным боссом-драконом!

## Геймплей и особенности, концепция

- **Слоистая структура карты**: Глобальный граф локаций разделен на вертикальные слои. Игрок видит взаимосвязи между комнатами, планирует маршрут и продвигается от старта к боссу

- **Интерактивные механики комнат**: в данный момент в игре представлены такие механики комнат:
* **Артефакты**(OneTimeEvent) - случайные зачарования оружия(Огонь, Лёд) на основе встроенного алгоритма генерации случайных чисел
* **Походная кузница** - зона полировки и усиления снаряжения.
* **Древний алтарь** - механика благословения и исцеления раненого персонажа.
* **Торговец** - Торговля за заработанную валюту

- **Полная свобода перемещения** - Благодаря ветвистой системе навигации, игрок может свободно возвращаться назад по ранее открытым связям, если это необходимо.

- **Полная свобода перемещения** - Бой с боссом завязан на прицельные атаки по конкретным частям тела, каждая из которых обладает индивидуальным множителем урона

- **Система сохранений** - архитектура позволяет сохранять прогресс и характеристики персонажа в JSON-файл в любой момент навигации по карте и беспрепятствено загружать его при следующем запуске

## Управление в игре

Взаимодействие с игрой происходит через ввод цифр в консоль с последующим нажатием клавиши `Enter`. Интерфейс снабжен полной защитой от некорректного ввода (букв, пустых строк или недопустимых индексов).

- **1, 2, 3...** - Выбор направления для перехода на карте или выбор части тела противника для атаки в бою.
- **8** - сохранить текущий игровой процесс (`savegame.json`)
- **7** - Загрузить последнее сохранение.
- **9** - Отменить последнее действие(Оно вам не нада)
- **0** - Выход из игры

## Инструкция по запуску

Для запуска игры не требуется установленная среда разработки (Visual Studio / Rider) или .NET SDK. Просто переходите по релизу и скачивайте игру для нужной вам ОС

## Архитектурные Решения

Архитектура проекта спроектирована с акцентом на слабую связанность компонентов (Loose Coupling), расширяемость и строгое разделение логики и представления (MVC / UI Separation).

1. Паттерн Фабрики (Factory)
   * Файл: `LocationFactory.cs` и т.п
   * Изолирует логику инстанцирования объектов.

2. Паттерн Стратегия (Strategy)
   * Файлы: `ILocationBehavior.cs`, `EventLocationBehavior.cs`, `AltarLocationBehavior.cs` и т.п
   * Используется для реализации полиморфного поведения локаций при входе игрока в комнату `(OnEnter)`. Объекты класса `Location не знают внутренней специфики того, что в них происходит. Они лишь делегируют выполнение подключенной стратегии, что позволяет добавлять неограниченное число новых механик, не меняя базовый класс локации

3. Паттерн Команда (Command)
   * Файлы: `ICommand.cs`, `MoveToNodeCommand.cs`, `CommandHistory.cs`
   * Инкапсулирует запросы на перемещение игрока между узлами графа в виде отдельных объектов.

4. Патерн Строитель (Builder)
   * Файлы: `MapBuilder.cs`, `BossBuilder.cs` и т.п
   * Позволяет пошагово конструировать сложные иерархические структуры. Кратко говоря, упрощают создание новых конструкций

5. Патерн Строитель (Builder)
   * Файлы: `GameContext.cs`, `IGameState.cs`, `MenuState.cs` и т.п
   * Управляет глобальными макро-состояниями игрового приложения. Упрощает код `if/else`

## Стабильность и Обработка Ошибок (UX/Polish)

1. **Защита от сбоя парсинга** (FormatException): Считывание пользовательских команд переведено на метод `int.TryParse`. Ввести что-то неверное - невозможно
2. **Безопасная десериализация**: Логика GameSaver.LoadGame() обернута в защитные блоки try-catch. Если файл сохранения поврежден, пуст или содержит некорректный JSON, игра выдает понятное предупреждение и предлагает начать новую сессию без вылета приложения.
3. **Плавность консоли**: Весь отладочный мусор `(Console.WriteLine("TEST"))` вычищен. Переходы между экранами сопровождаются очисткой буфера `(Console.Clear)`
